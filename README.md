# 漾澤 drshinehair｜年度營運儀表板 V01

沿用愛美肌定稿四頁架構，獨立淺藍版。資料期間由私人來源決定，不在程式與本文件內建。

## 安全架構

- 公開儲存庫只有程式，不含 PDF、營運數字、目標值、存取權杖或密碼。
- Google 登入使用 Sheets 唯讀授權；實際存取由來源 Sheet 共用權限決定。
- 來源 Sheet 僅以「指定人員」共用，不得使用「知道連結的人」。
- Google OAuth Client ID 不是密碼，不得加入 Client Secret。
- 共用既有已授權的正式網域登入設定，不修改愛美肌程式或資料。
- 資料只存在登入後記憶體；登出、逾時、讀取失敗清除資料，不使用持久化儲存。

## 結構與更新

- `dashboard.template.html`：固定淺藍四頁版型。
- `dashboard-data.js`：月份、分店、新舊客、資料完整性與加總驗證。
- `dashboard.js`：Google 登入、即時讀取、篩選、每 5 分鐘可見頁面更新。
- `config.js`：來源 Sheet 識別碼與公開 OAuth client ID。
- `node build_v02.js`：檢查語法並產生 `index.html`。
- `node --test dashboard.test.js`：合成測試資料，不含真實營運數字。

## 計算規則

- 新客實績固定採依預約日期的新客到店數，不是消費數或客服詢問數。
- 所有分店同月份完整匯入才顯示；不跨月去重。
- 新客目標由來源 Sheet 提供，未知為空白；任一所選項目缺目標，不顯示達成率與落後數。
- 消費金額、消費數、到店數按月份／客群與月報總覽核對。
- 平均客單＝金額÷到店數，累積以總額總數重算；中位數不加總。
- Meta 僅用平台詢問數，CPA＝已配對訊息花費÷平台詢問數。
- Meta 分店歸屬先看廣告組合名稱，再看行銷活動名稱；廣告組合已標示桃園、三峽、江翠或板橋時，必須歸入對應分店，不得被上層「品牌」活動覆蓋。只有兩層都無法判定分店的共用花費才列入「品牌整體」。
- 未知廣告花費及預算不當成 0，缺資料明確標示。
- Meta 與年度預算的同月花費不一致會停止顯示。
- Meta 預算來源分流：全品牌檢視讀取「年度預算」H 欄；單店檢視讀取「Meta月度KPI」G 欄，G 留白代表未知、0 代表確認無預算。
- 分店 Meta 預算完整性只檢查桃園、江翠、三峽三店；「品牌整體」不列必填，但已有 G 欄金額仍納入當月配置總額與年度預算差額計算。
- 來源 Sheet 的年度預算整頁受保護，只開放非 Meta 平台的 L 欄實際花費；Meta月度KPI 開放 G2:G49（含品牌整體）供 PM 填寫，品牌整體不列完整性必填但有值時納入月總額。
- 本機 `file://` 來源不支援 Google 登入；正式版使用已授權的 HTTPS 來源。

私人驗收、月報、日誌、目標值、Sheet 位址與範圍、帳號清單與數值匯出皆保存在本機／AI 工作中樞，不加入 Git。
